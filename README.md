# Заметки

Приложение для заметок: бэкенд на Laravel, фронтенд на React + Vite + Tailwind.

| Каталог     | Что внутри                                       |
| ----------- | ------------------------------------------------ |
| `backend/`  | Laravel API                                      |
| `frontend/` | React-приложение                                 |
| `devops/`   | Docker Compose: nginx, php-fpm, PostgreSQL, node |
| `docs/`     | Спецификация API (`openapi.yaml`)                |

## Запуск

Нужны Docker с Compose и `make`.

```sh
make init
```

`init` подготавливает проект с нуля:

1. Создаёт `devops/docker/.env` из примера с UID/GID текущего пользователя и `backend/.env`, если их ещё нет, и генерирует `JWT_SECRET`, если он пустой.
2. Собирает образы и поднимает контейнеры.
3. Ставит composer-зависимости, генерирует `APP_KEY`, если он пустой, и применяет миграции.

npm-зависимости фронтенда ставятся сами при первом старте контейнера `node`.

После этого приложение доступно на `http://localhost` (порт задаётся `NGINX_PORT` в `devops/docker/.env`). Дальше достаточно `make up` и `make down`.

## Команды

Список команд выводит `make` без аргументов. Аргументы для команд-обёрток передаются через `c`:

```sh
make artisan c="route:list"
make logs c=node
```

### Контейнеры

| Команда        | Что делает                                               |
| -------------- | -------------------------------------------------------- |
| `make init`    | Первый запуск: `.env`, сборка, зависимости, ключ, миграции |
| `make env`     | Создать `.env` из примеров и сгенерировать `JWT_SECRET`  |
| `make up`      | Запустить проект в фоне                                  |
| `make down`    | Остановить проект                                        |
| `make restart` | Перезапустить контейнеры                                 |
| `make build`   | Собрать образы                                           |
| `make rebuild` | Пересобрать образы без кэша и перезапустить              |
| `make ps`      | Статус контейнеров                                       |
| `make logs`    | Логи всех сервисов или одного: `make logs c=node`        |

### Консоли

| Команда     | Что делает                 |
| ----------- | -------------------------- |
| `make php`  | Shell в контейнере php-fpm |
| `make node` | Shell в контейнере node    |
| `make psql` | Консоль PostgreSQL         |

### Бэкенд

| Команда         | Что делает                                       |
| --------------- | ------------------------------------------------ |
| `make composer` | Composer: `make composer c="require foo/bar"`    |
| `make artisan`  | Artisan: `make artisan c="route:list"`           |
| `make migrate`  | Применить миграции                               |
| `make fresh`    | Пересоздать БД и заполнить 500 тестовыми заметками (данные удаляются) |
| `make test`     | Тесты бэкенда, фильтр: `make test c="--filter=Note"` |

### Фронтенд

| Команда            | Что делает                          |
| ------------------ | ----------------------------------- |
| `make npm`         | npm: `make npm c="install foo"`     |
| `make lint`        | Линтер фронтенда                    |
| `make build-front` | Production-сборка фронтенда         |

## Что нужно будет доработать

### Запуск и инфраструктура

- **Production-сборка.** Сейчас Docker Compose рассчитан только на разработку: nginx проксирует dev-сервер Vite. Нужна сборка фронтенда в статику и отдельный compose-файл или образ для продакшена.
- **CI.** Прогон тестов, Pint и линтера фронтенда на каждый пуш.

### Бэкенд

- **Пользователи и владельцы заметок.** Токен ни к кому не привязан (нет claim `sub`), а у заметок нет `user_id`, так что любой, кто получил токен, видит и меняет все заметки. Нужны регистрация и вход, и выборка только своих заметок.
- **Ограничение частоты запросов.** `POST /auth/token` открыт и ничем не ограничен, токены можно выпускать без конца. Стоит добавить `throttle` на эндпоинты авторизации и API.
- **Тесты.** В первую очередь нужны feature-тесты на CRUD заметок, валидацию и пагинацию и unit-тесты `JwtService`: истечение, refresh, отзыв, повторный refresh.
- **Массовое удаление.** Фронтенд удаляет выбранные заметки параллельными `DELETE /notes/{id}`, и результат не атомарный. Можно добавить один эндпоинт с удалением в транзакции.
- **Статический анализ.** Larastan (PHPStan) в `require-dev`.

### Фронтенд

- **Хранение токена.** Токен лежит в `localStorage` и доступен любому скрипту на странице при XSS. Надёжнее отдавать его в `httpOnly`-cookie.
- **Тесты.** Vitest и Testing Library: API-клиент (обновление токена, ошибки) и основные сценарии форм.
- **Поиск и сортировка** по списку заметок. Это требует поддержки в API.
- **Свои чекбоксы** в стиле остального интерфейса вместо нативных.

### Возможные фичи

- Авторизацию, регистрацию пользователя
- Корзина с восстановлением через soft deletes вместо окончательного удаления.
- Закреплённые заметки, теги или цвета карточек.
- Чек-листы для заметок
- Сортировку, фильтрацию и поиск
